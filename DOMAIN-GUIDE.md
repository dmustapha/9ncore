## Core Concepts

- **euint128**: Encrypted uint128. FHE operations return handles (bytes32), not values. Never log or display raw handles. All ETH amounts in PrivLend use euint128 because euint64 overflows at ~18 ETH in wei. Stored on-chain as `uint256` pointers; actual values live with the off-chain coprocessor.

- **ebool**: Encrypted boolean. Stored as a handle on-chain. Decrypted via Gateway by an authorized address. Used for the `_healthFlag` — only the liquidator has ACL permission to decrypt it.

- **ACL (Access Control List)**: Per-handle permission system. `FHE.allow(handle, addr)` grants `addr` decryption rights via the Gateway. Every handle must be explicitly allowed for every address that needs to read it. Forgetting an `allow` call means the user can never decrypt their balance.

- **allowThis**: `FHE.allowThis(handle)` grants the contract itself permission to use a handle in future transactions. Must be called immediately after any FHE op that produces a new handle — before the function returns. Without it, the contract loses access on the next call.

- **fromExternal**: `FHE.fromExternal(einput, inputProof)` validates a user-submitted encrypted input against an ACL proof from the user's wallet. Always the first FHE operation on any user-supplied encrypted parameter. Used in `deposit()`, `borrow()`, and `repay()`.

- **Gateway**: Zama's decryption relay. Borrowers call `userDecrypt` from the relayer-SDK to request their handle decryption. The Gateway verifies ACL permissions and returns the plaintext to the authorized user only. URL: `https://gateway.sepolia.zama.ai`.

- **LTV (Loan-To-Value)**: PrivLend uses a fixed 150% LTV ratio — $150 of collateral required for every $100 borrowed. No oracle. Enforced by `LTV_DENOMINATOR = 150` in the contract. A borrower's position is healthy while `collateral * 100 >= debt * 150`.

- **Health factor**: The contract stores `_healthNumerator[borrower]` = `collateral × 100` as a euint128. The frontend divides by the decrypted debt to display the actual ratio. The liquidator sees only `_healthFlag` (ebool: is position healthy?).

- **Liquidation**: Anyone can liquidate an unhealthy position (`_healthFlag == false`). The liquidator pays ETH, receives the borrower's collateral plus a 5% bonus. Partial liquidation uses `FHE.min(debt, repayEncrypted)` so the liquidator can never take more than the full outstanding debt.

- **Encrypted amounts**: All user amounts are encrypted client-side by the relayer-SDK before submission. The contract never sees plaintext balances. ETH is deposited as native ETH (payable functions); the encrypted handle represents the accounting layer.

- **coprocessor**: Off-chain service that computes actual FHE math. The EVM only stores handles and emits events. The coprocessor executes the FHE operations asynchronously and writes results back as handles.

- **inputHandle / inputProof**: The `bytes32` handle pointer returned by the relayer-SDK after encrypting user input, paired with the proof that the ciphertext is valid and authorized. Passed together to `fromExternal`.

- **userDecrypt / reencryption**: The relayer-SDK operation where a user proves wallet ownership and the Gateway re-encrypts the handle under the user's public key, returning a plaintext they can read. Used on the frontend for "My Collateral" and "My Debt" displays.

| Operation | Usage in Contract | Notes |
|-----------|------------------|-------|
| `FHE.fromExternal` | deposit, borrow, repay — validate user input | Always first FHE op on user input |

| `FHE.allowThis` | after every FHE op that produces a new handle | mandatory — contract loses access without it |
| `FHE.allow` | grant borrower access to collateral/debt handles; grant liquidator access to healthFlag | must call for each authorized address |

## Key Rules (must not violate)

1. **allowThis is mandatory immediately after every FHE op.** The contract loses access to any handle it creates if `allowThis` is not called before the function returns. Pattern: `euint128 result = FHE.add(a, b); FHE.allowThis(result);`

2. **Never store a handle without allowThis.** Storing an unallowed handle and reading it next call will revert or return garbage.

3. **`FHE.allow(handle, user)` must be called for each user who needs to decrypt.** Collateral/debt handles: allow the borrower. healthFlag: allow the liquidator only.

4. **Interest accrual only at repay time.** Never compute interest in view functions. At repay, compute `elapsed = block.number - _lastInterestBlock[borrower]` in plaintext, then `FHE.mul(debt, FHE.asEuint128(elapsed * BPS_PER_BLOCK))` to add accrued interest.

5. **Partial liquidation via FHE.min.** `repayHandle = FHE.min(_debt[borrower], repayEncrypted)` ensures the liquidator never over-repays. Liquidation bonus is calculated off the actual repaid amount.

6. **DEV-001: No scalar plaintext multiply for euint128.** `FHE.mul(euint128, uint8)` does not exist. Always use `FHE.mul(debt, FHE.asEuint128(uint256(bps)))`. BPS values must fit in uint256 (they do — max uint8 = 255).

7. **euint128 for all amounts.** euint64 overflows at ~18.4 ETH in wei. Use euint128 everywhere to support realistic collateral values.

8. **Direct ETH custody.** No cWETH wrapper. Deposit functions are `payable`. The contract holds raw ETH. The encrypted handle tracks the accounting.

## Glossary

| Term | Definition |
|------|-----------|
| **Handle** | `bytes32` identifier returned by FHE ops — not the encrypted value itself |
| **InputProof** | Zama proof that the client-side ciphertext is valid and authorized |
| **Reencryption** | Re-encrypting a handle under a different public key (for user viewing via Gateway) |
| **coprocessor** | Off-chain FHE computation engine — actual math happens here, not on EVM |
| **healthFlag** | `ebool` — is this position above the LTV threshold? Liquidator-only ACL |
| **healthNumerator** | `euint128` = collateral × 100. Borrower decrypts and divides by debt to get ratio |
| **inputHandle** | `bytes32` pointer to encrypted user input, produced by relayer-SDK |
| **LTV_DENOMINATOR** | Fixed constant `150` — 150% collateral required per 100 borrowed |
| **LIQUIDATION_BONUS_BPS** | `500` = 5% bonus paid to liquidator on seized collateral |
| **BPS** | Basis points: 1 BPS = 0.01%. Interest rate is expressed in BPS per block |
| **FhevmInstance** | Client-side relayer-SDK object: `createInstance({ kmsContractAddress, aclContractAddress, network, gatewayUrl })` |
| **userDecryptHandle** | Frontend helper that calls `instance.reencrypt(handle, { publicKey, signature })` and returns plaintext bigint |

## Common Mistakes (avoid these)

- **Forgetting `allowThis` after FHE ops** → contract can't access handle on next call, silent corruption
- **Using `FHE.mul(euint128, uint8)`** → compile error "no matching overload" — use `FHE.asEuint128()` wrapper (DEV-001)
- **Importing from `@fhevm/solidity` without checking version** → always pin to the version in package.json
- **Calling `createInstance` on server-side** → WASM only works in browser; guard with `typeof window !== 'undefined'`
- **Missing `asyncWebAssembly: true` in next.config.js** → silent import failure of relayer-sdk/web
- **Returning plaintext in view functions** → all state is encrypted; view functions return handles, not values
- **Skipping `fromExternal` validation** → contract accepts invalid ciphertexts, undefined behavior
